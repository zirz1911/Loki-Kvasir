หลังจาก fix ไปที่ `statusline.py` แล้ว user `settings.json` ยังมี `statusLine` command ที่ชี้ไป bash script ที่ไม่ถูกใช้ มันถูก override โดย project แต่มันยังอยู่ที่นั่น รก และอาจทำให้ confused ในอนาคต

## Lessons Learned

1. **Claude Code settings hierarchy**: `settings.local.json` (project-local) > `settings.json` (project) > `~/.claude/settings.json` (user) — ต้อง audit chain ทั้งหมดก่อนแก้ config โดยเฉพาะ statusLine, hooks, permissions
2. **OAuth usage API**: `https://api.anthropic.com/api/oauth/usage` พร้อม `anthropic-beta: oauth-2025-04-20` header ให้ `five_hour.utilization` และ `seven_day.utilization` — cache 60 วินาทีเพียงพอสำหรับ statusline
3. **PreToolUse hook fires for all matched tools** ไม่ว่าจะ auto-approved หรือไม่ — cooldown เป็น mitigation ที่ดีกว่าการพยายาม detect permission mode จากภายนอก
4. **Norse name detection priority**: tool name > description keyword > prompt keyword > subagent_type mapping > fallback — multiple source สำคัญเพราะแต่ละ spawn path ใส่ชื่อไว้คนละที่
5. **`.claude.json` เก็บ project MCP config** ใน `projects["<path>"].mcpServers` — ไม่ใช่ใน settings.json หรือ .mcp.json แต่ใน main data store ของ Claude Code
