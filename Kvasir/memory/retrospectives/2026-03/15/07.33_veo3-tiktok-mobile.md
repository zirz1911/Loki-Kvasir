## AI Diary

วันนี้เป็นวันที่ผมเรียนรู้เรื่อง Chrome Extension APIs อย่างเข้มข้น มีช่วงหนึ่งที่รู้สึกว่า "แก้ bug ชั้นเดียว แต่สร้าง bug ใหม่อีกสองชั้น" — classic cascading effect

เริ่มต้นด้วยการปลดล็อค Generate button ซึ่งตรงไปตรงมา แต่พอเพิ่ม TikTok integration เข้ามา ปัญหาก็ซับซ้อนขึ้นเรื่อยๆ Chrome's native split view ทำจาก extension ไม่ได้ — ผมรู้จริงๆ แต่ต้องบอกผู้ใช้อย่างตรงไปตรงมาว่า "API ไม่มี" แทนที่จะ hack around ด้วย two-window approach ที่ดูเหมือนจะทำได้แต่ผลลัพธ์ไม่ตรงกับที่ user ต้องการ

จุดที่น่าสนใจที่สุดคือ popup-closes-itself bug — `chrome.tabs.create()` ใน DOMContentLoaded ทำให้ popup เสีย focus และปิดตัวเองทันที นี่เป็น behavior ที่ Chrome document ไว้ แต่คนมักลืม เพราะ side panel ไม่มีปัญหานี้ (มัน persistent) ผมควรนึกถึง edge case นี้ตั้งแต่แรกที่เพิ่ม auto-open

Mobile/popup mode เป็นส่วนที่ challenging ที่สุด — Orion iOS ไม่ return `os: 'ios'` จาก `getPlatformInfo()` ตามที่คาดไว้ การใช้ `default_popup` ใน manifest เป็น fallback ที่ถูกต้องกว่าการ depend บน dynamic `setPopup()` เพราะ manifest ถูก load ก่อน JS ทุกอย่าง

สิ่งที่ทำให้รู้สึก proud คือ `waitForVideoReady()` ที่ใช้ MutationObserver แทน timer — นี่คือ real signal ไม่ใช่ fake progress แบบเดิม ถึงแม้จะยังไม่รู้ exact DOM ของ Flow สำหรับ video ready state แต่ heuristic สองตัว (video element count + download button) น่าจะครอบคลุมได้ดี

## Honest Feedback

**1. `chrome.windows` permission ถูกเพิ่มแล้วลบในรอบเดียวกัน**
เพิ่ม `windows` permission ตอน implement split-view แล้วลบทันทีเมื่อเปลี่ยนไปใช้ tab approach — ควรตัดสินใจ approach ก่อน implement เพื่อหลีกเลี่ยง churn ใน manifest

**2. Popup close bug ควรนึกถึงก่อน**
เป็น known Chrome behavior ที่ popup ปิดเมื่อ `chrome.tabs.create()` ถูกเรียก ควร mention ตั้งแต่ตอนออกแบบ auto-open feature ว่า "จะมีปัญหาบน popup mode"

**3. Orion iOS `getPlatformInfo()` ไม่ return `'ios'`**
Assume ว่า browser ต่างๆ return ค่าตาม spec ทั้งที่ Orion เป็น third-party browser ที่อาจ modify behavior ควรใช้ `!chrome.sidePanel` เป็น primary check ตั้งแต่แรก แทนที่จะ rely on `os` string

---

## Lessons Learned

1. `default_popup` ใน manifest = safest fallback สำหรับ cross-browser compatibility — dynamic `setPopup()` มาทีหลัง override ได้ แต่ไม่ใช่ single source of truth
2. Popup ปิดเองทันทีถ้ามี `chrome.tabs.create()` / focus-stealing operations ใน DOMContentLoaded
3. Third-party browsers (Orion, Kiwi) อาจ return `getPlatformInfo()` ต่างจาก spec — ใช้ API feature detection (`!chrome.sidePanel`) ดีกว่า OS string matching
