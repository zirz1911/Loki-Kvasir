## Honest Feedback

**1. The dummy cards are removed but could flicker on reload.** When `/email-history` returns results and `addEmailCard` is called, `emailCount` starts at 0 so the first call removes dummies. But there's a brief moment between page load and the fetch completing where dummies are visible even if there's history. Low impact but worth noting.

**2. No way to copy email body to clipboard.** For an OTP board, the main action after reading the OTP is using it somewhere. A click-to-copy on the body (or just the detected OTP code) would save steps. SMS messages have the same limitation but email bodies can be longer so the need is more acute.

**3. Email history isn't separated from SMS clear.** The auto-clear at 5 minutes clears both `history` and `emailHistory` together, and the `_clear` SSE event calls `clearEmailBoard(true)` silently. This makes sense for consistency but means email data has the same 5-minute TTL as SMS. If email OTPs take longer to act on, this could be a problem.

## Lessons Learned

- Dummy placeholder cards are a useful UI pattern for monitoring tools — they set expectations about information shape before real data arrives
