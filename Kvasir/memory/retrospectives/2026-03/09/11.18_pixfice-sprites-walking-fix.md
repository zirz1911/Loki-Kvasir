## AI Diary

The walking-backwards bug was already fully diagnosed in the previous session context before compaction. I had the fix ready to write — it was just a matter of applying it cleanly. The root cause was clear from the Python script analysis: `make_walk(f=1)` shifts leg pixels left, which is forward for a left-moving character but backward for a right-moving one. The fix was simple: stop using `walkFrame % 4` uniformly for all directions. For LEFT, alternate 0↔1. For RIGHT, alternate 0↔3. UP/DOWN can keep the full 4-frame cycle because there's no mirroring issue.

The Office sprite swap was more interesting. I felt confident about the approach — CSS crop technique is clean, no canvas needed, just `overflow: hidden` + negative margins on the `<img>`. The `ChibiSprite` component I built was actually quite tidy. But Lokkji looked at it and immediately said "มันแปลก" (it looks weird). He's right — the chibi PNG sprites, at 32×48px, probably looked inconsistent against the pixel-art desk furniture and room styling. The Office view was designed with the CSS box-shadow sprites which are intentionally tiny and abstract. Dropping photo-realistic-ish chibi sprites into that context creates a style mismatch.

I should have anticipated this. The Game view works because the whole canvas is a top-down game world — the chibi sprites belong there. The Office view is a card-based UI with pixel-art accents. The avatars need to feel flat and iconographic, not character-art. I made the classic mistake of assuming "bigger/more detailed = better."

The revert was clean. I kept `ChibiSprite.tsx` in the codebase since Lokkji said he'd get new sprites — it will be ready when the new assets arrive. The `agentCharIdx` function is now duplicated between `GameCanvas.tsx` and `ChibiSprite.tsx`, which is mild tech debt, but acceptable until the sprites situation is resolved.

One thing I notice: this session was almost entirely reactive — Lokkji drove every decision. I didn't propose anything proactively. That's appropriate for a bug-fix + style session, but I could have warned earlier that the sprite style might clash with the Office card aesthetic.

## Lessons Learned

1. **Style consistency > technical correctness**: A component that renders correctly but clashes with the surrounding visual language is still wrong. Before swapping a visual element, consider whether the new asset belongs in that context's aesthetic.

2. **Direction-aware animation requires direction-aware frame selection**: Walk cycle frames that look natural from one direction will look unnatural from the mirror direction if the underlying pixel deltas are not symmetric. This is a fundamental spritesheet authoring + playback concern.

3. **Keep orphaned components in-tree when future use is likely**: `ChibiSprite.tsx` is unused by Office but kept because new sprites are coming. Don't delete work that's likely to be reactivated soon — just leave it dormant.

4. **CSS crop technique for spritesheets is clean**: `overflow: hidden` + negative `margin-left/top` on a full-size `<img>` is simpler than canvas for static or interval-animated frames. Worth remembering for next sprite integration.
