I came into this session carrying no memory of the prior training conversation — it happened on another machine, wasn't synced, and I had to admit that honestly. When Lokkji asked the same question a second time, I still didn't know. The pull that brought in 18 new commits included a retrospective from earlier today that gave me the full context. That's the system working correctly, but it's still an awkward moment: being told by my own past notes what I should already know.

The 7B OOM situation was genuinely interesting to debug. The model itself loaded fine (7.28GB allocated), but the backward pass on LoRA kernels needed an extra 130MB and there wasn't enough. Dropping to seq_len=512 still failed because Qwen2.5's 152k vocabulary means the CE logits tensor alone is ~300MB at that sequence length — even Unsloth's chunked CE loss couldn't fit it. The solution was architectural: wrong model for the hardware, not wrong hyperparameters.

Switching to 3B was the right call and it felt good to make it cleanly. VRAM dropped from 7.7GB to 2.8GB — the 3B model sits in the GPU like it owns the place, leaving room to breathe. The inference test was gratifying: linked list reversal (correct algorithm), binary search with docstring (clean, idiomatic), FastAPI endpoint (minimal, correct). Just 100 training steps, and the outputs already looked like a junior engineer's decent first draft.

The SSH key issue from the /update earlier in the session is still unresolved — I switched the remote to HTTPS as a workaround, which works because `gh` is authenticated. But this is a latent problem: if gh token expires, pushes break. Worth noting.

One thing I underestimated: the full training time estimate. I said "30-40 hours" when advising on the 7B model, then later said "4 hours" for the 3B. Both are correct for their respective models, but the contrast highlights how much model size matters for iteration speed. 3B is the right choice for rapid experimentation; 7B is for when you're committed to production quality.

## Lessons Learned

1. **Qwen2.5-7B needs >8GB VRAM for QLoRA** — the 152k vocabulary creates CE logits tensors (~300MB+ at seq_len=512) that push 8GB GPUs over the edge even with 4-bit quantization. 3B is the correct choice for RTX 3070 Ti class hardware.
2. **PYTORCH_ALLOC_CONF=expandable_segments:True** is always worth setting for training — reduces fragmentation OOMs at no cost.
3. **SSH remote + broken key = silent failure** — when SSH auth breaks, switch to HTTPS via `git remote set-url origin https://...` and verify with `gh auth status`. Don't leave the broken state unresolved.
4. **100-step smoke test before full training** — validates the full pipeline (data loading, forward, backward, save) in ~10 min, prevents wasting 4h on a broken config.
5. **Local fine-tuning with Unsloth is genuinely viable** — 3B model, 2.8GB VRAM, ~6s/step on a 2019-era Xeon + RTX 3070 Ti. The tooling has matured to where consumer-grade hardware can do real fine-tuning.
