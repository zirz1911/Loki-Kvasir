## AI Diary

Today was a day of fighting infrastructure rather than building things. It started cleanly enough — check ComfyUI, download some models — but quickly turned into a permissions battle. Three different model folders owned by root: `loras/`, `upscale_models/`, `checkpoints/`. Each one required a separate `sudo chown`, and each time we had to wait for the user to run it in their terminal because we can't sudo ourselves. The rhythm of that back-and-forth was slow and a little frustrating, but each fix unblocked the next thing.

The LTXVideo node folder issue was interesting in a different way. The node code hardcodes `checkpoints/` as the folder for the main LTX model, even though conceptually it belongs in `diffusion_models/`. This is a node-level design decision we can't change without patching the source. Symlinks are the right answer here — they let us keep files in semantically correct locations while satisfying what the node expects.

The OOM during VAEDecodeTiled was predictable in retrospect. RTX 3070 Ti with 8GB VRAM trying to decode a 22B model's output all at once. The fix — `LTXVSpatioTemporalTiledVAEDecode` — is elegant: it tiles both spatially AND temporally, so VRAM usage stays bounded regardless of video length or resolution.

The most interesting moment was when LTX-2.3 actually started generating — `Generating tokens: 0/256 [00:57<?, ?it/s]` — after all the setup friction. The model IS working. It's just going to be slow. A 22B model on 8GB VRAM with CPU offloading is not the intended deployment scenario, but it runs.

The user tried Wan2.1 as an alternative and didn't like it. Fair enough — different aesthetic, different feel. LTX-2.3 has its own character. Sometimes the slower, harder thing is worth it.

## Honest Feedback

**Friction point 1 — Root-owned ComfyUI model folders**: All model subdirectories were owned by root, requiring multiple rounds of `sudo chown`. This is probably from the initial ComfyUI install being run as root. We should have caught this at the start and fixed all folders at once (`sudo chown -R paji:paji /home/paji/Project/ComfyUI/models/`) instead of discovering each one individually as downloads failed. Time lost: ~20 minutes of back-and-forth.

**Friction point 2 — LTXVideo node hardcodes checkpoints/ folder**: The `LTXAVTextEncoderLoader` and `LTXVAudioVAELoader` nodes scan `checkpoints/` for what is semantically a diffusion model. This is confusing and undocumented. The workaround (symlink) works but is fragile — if ComfyUI ever cleans symlinks or the node gets updated to use a different folder, it breaks silently. Ideally we'd patch the node to scan `diffusion_models/` instead.

**Friction point 3 — Queue persistence causing stuck UI**: ComfyUI's UI spun indefinitely multiple times because there were queued/interrupted jobs that kept re-running on startup. The fix was `POST /queue` with `{"clear": true}` + `POST /interrupt`, but we only discovered this after multiple kill-and-restart cycles. ComfyUI should probably have a "clear queue on startup" option for recovery situations.

## Lessons Learned

1. **Fix all ComfyUI model folder permissions at once**: `sudo chown -R paji:paji /home/paji/Project/ComfyUI/models/` — do this before downloading anything
2. **ComfyUI-LTXVideo expects main model in `checkpoints/`** — use symlink from `diffusion_models/` to `checkpoints/`
3. **LTX spatial upscaler goes in `latent_upscale_models/`** — not `upscale_models/`
4. **For 8GB VRAM + LTX-2.3**: use `LTXVSpatioTemporalTiledVAEDecode` with `spatial_tiles=2`, `temporal_tile_length=8`, `working_device=cpu`
5. **Clear stuck ComfyUI queue via API**: `curl -X POST localhost:8188/queue -d '{"clear":true}'`
