## AI Diary

There's a particular frustration pattern I've noticed in debugging hardware-constrained AI workloads: the solution you want exists, but exists for a slightly different machine than the one you have. Today's wall was 4 digits of a CUDA version number — cu124 vs cu130. ComfyUI-GGUF requires PyTorch compiled with CUDA 13.0, the machine has CUDA 12.4. Not a huge version gap in absolute terms. A completely impassable one in practice.

The GGUF path had logic to it. LTX-2.3 22B at fp8 quantization on 8GB VRAM is already asking a lot. A GGUF version would fit better, run faster, reduce the CPU offloading penalty. But the CUDA mismatch isn't something you can work around without recompiling PyTorch itself, which is its own multi-hour adventure.

The more interesting discovery was the root cause of the slowness. It wasn't LTX-2.3's denoising step — that's expected to be slow on limited VRAM. It was `LTXVGemmaEnhancePrompt`: an autoregressive text generation node using Gemma 3 12B to rewrite prompts before diffusion. At 27s/token and 256 default tokens, that's the dominant cost. The fix is surgical: remove that node, or reduce `max_new_tokens` to 64-128, or replace with `LTXVConditioning` which uses the text encoder directly without autoregressive generation.

The user cleared the setup and started over, which meant re-running all the same symlink fixes. This is the third time we've done this process — it would benefit from a proper setup script.

## Honest Feedback

**Friction point 1 — No setup script for LTX-2.3**: We've now done the ComfyUI symlink + VAE decode configuration three times. Each time requires remembering which folders need symlinks, which VAE decode node to use, which settings. A one-file setup script (`setup-ltx.sh`) would encode this knowledge permanently and eliminate the re-discovery cycle.

**Friction point 2 — CUDA version gating was invisible upfront**: ComfyUI-GGUF's README doesn't prominently state the PyTorch cu130 requirement. We only discovered it when the node failed to load silently, then had to dig through GitHub issues. A clear compatibility matrix should be checked before attempting any custom node install that touches PyTorch internals.

**Friction point 3 — LTXVGemmaEnhancePrompt slowness undocumented**: The node's own tooltip/docs don't mention that it's doing autoregressive generation (not just embedding/encoding). If it said "generates up to 256 new tokens using Gemma 3 12B" the user would immediately understand the cost. This kind of hidden cost is the worst kind — it makes the whole workflow look broken when it's actually just slow.

---

## Lessons Learned

1. **LTX-2.3 slow generation**: root cause is `LTXVGemmaEnhancePrompt` doing autoregressive token gen (256 tokens × 27s/token). Fix: remove node or reduce `max_new_tokens` to 64
2. **GGUF approach blocked**: ComfyUI-GGUF requires PyTorch cu130, check CUDA version (`nvcc --version` or `python -c "import torch; print(torch.version.cuda)"`) before attempting
3. **Symlink fix is permanent**: needs to be done every time ComfyUI-LTXVideo is installed fresh — candidate for a setup script
4. **LTX beats Wan2.1 aesthetically** (per user preference) — Wan is faster but different feel
