## AI Diary

This session had a satisfying texture to it — the kind where every task is small and contained but the cumulative result feels like the product grew up a bit. We started in the middle of a half-finished fix (the video failure false-positive) and immediately pushed it. Then it was one clean problem after another.

The TikTok tab navigation bug was a nice diagnosis moment. The code was checking `https://www.tiktok.com/tiktokstudio/*` but not caring *which* page within that domain — so if you had the analytics page open, it'd try to upload there. Simple fix: check if URL includes `/upload`, navigate if not. I like bugs like that — they have a clear cause and a clear fix.

The exo-paji theme was the most visually dramatic change. Replacing orange with terminal green oklch, adding the Silkscreen font, grid background, CRT scanlines — all in one pass across a 1000+ line CSS file. It required careful search-replace because there were many hardcoded `rgba(249, 115, 22, X)` values that couldn't be caught by variable replacement alone. Satisfying to clean that up systematically.

The toggle switch was probably the most delightful UX improvement. Replacing a text button ("⏸ หยุด / ▶ เปิด") in the actions row with an inline CSS toggle switch directly on the card header — that's the difference between "functional" and "feels good to use."

The content script readiness fix was the most important reliability fix. The 500ms hardcoded delay is a classic Chrome extension antipattern — it works when everything is warm, fails silently when tabs are discarded. Adding ping/pong with retry is the proper solution. Twenty retries at 1.5s each gives 30 seconds of patience, which covers even slow tab restores.

## Honest Feedback

**Friction point 1 — CSS replace_all race**: When doing the theme overhaul, I had to do multiple `replace_all` passes for different rgba opacity values (0.1, 0.2, 0.3, 0.4, 0.05, 0.06, 0.15). There's no way to do a "replace all rgba(249, 115, 22, \*)" with a wildcard in the Edit tool. This forced me into many sequential passes, and I had to grep after each pass to verify. A regex-replace capability in the Edit tool would be very useful here.

**Friction point 2 — Context carryover from previous session**: The session started with a summary of prior work, but I had to re-read background.js to verify the exact state of the code before making changes. The summary said "edit was applied but not committed" and I had to trust that without seeing the actual diff. Would be more reliable to have a `git diff` run at the start of every /rrr continuation.

**Friction point 3 — No way to test extension changes live**: All changes are push-to-GitHub and then manually reload in Chrome. There's no hot-reload or preview mechanism. This means each fix is a somewhat blind push — you have to trust the code review rather than seeing it in the browser. For CSS changes especially (like the theme overhaul), this is rough. A local test setup or screenshot capability would help a lot.

## Lessons Learned

- Chrome memory saver discards background tabs — never use fixed delays before sending content script messages; always wait for `tab.status === 'complete'` then ping-retry
- For CSS theme overhauls with many hardcoded color values, systematic grep-then-replace is the right approach; oklch colors are harder to replace globally than hex
- Toggle switch UX is almost always better than a label+button pair for binary state on a card
