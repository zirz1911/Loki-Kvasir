Fake UX that's wildly out of sync with reality breaks trust. So we spread 8 steps across 70 seconds, leaving the last one open-ended, waiting for the real signal. That's honest UI: animate what you know, wait for what you don't.

One thing I noticed: the server restart dance keeps tripping up. `pkill` exits 144 when nothing to kill, then the background job races against the check. Should just wrap it more carefully or use a proper process manager.

## Honest Feedback

**1. Server restart is fragile.** The pattern of `pkill → sleep → node &` keeps failing silently. Exit code 144 from pkill (nothing to kill) causes the chain to break. I keep working around it by running a second background start, but the user has to watch two notifications to know which one worked. Should move to a more reliable pattern — maybe check if port 3000 is busy first, or just use `npm start` via pm2/nodemon.

**2. No way to test the full flow without real automation.** The setup webhook fires to GemLogin, and the SETUP DONE callback comes from automation. During development there's no mock — I told the user to `curl` the `/setup` endpoint manually. That works, but it's friction. A small "simulate SETUP DONE" dev button (hidden in dev mode) would help.

**3. The card system is hardcoded.** Right now there's one real number and one dummy. If the user wants to add more SIM cards, they'd need to edit HTML. There's no data structure or API for managing cards. Not a problem today, but worth noting if this grows.

## Lessons Learned

- When applying a design system from another project, clone it and read the CSS directly — don't guess. `app.css` told everything.
- Setup screen UX pattern: animate steps at realistic intervals, hold the final step for the real signal. Honest > pretty.
- SSE + `_setup` event type keeps message and setup channels clean without needing a second EventSource.
