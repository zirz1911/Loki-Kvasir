## AI Diary

Two small bugs, both Android-specific, both with clean root causes.

The TikTok auto-open fix was simple — one line removed. The extension was eagerly opening TikTok Studio on every load, which on Quetta/Android probably caused issues because the browser doesn't expect extensions to spawn new tabs on startup. Moving it to "lazy" mode — only open when actually needed during the upload step — is the right behavior regardless of platform. It was premature optimization in the original design.

The file picker fix was more interesting. `input.click()` called from a JavaScript event handler is considered an "indirect" user gesture by Android's security model. The browser can't verify that the user actually tapped something — it might be a script running autonomously. So it blocks the file picker. The `<label for>` approach is elegant because it uses the browser's native form element behavior: tapping a label activates its associated input. No JS required. The browser knows it's a real tap because the label element itself received the touch event.

I notice these Android-specific issues keep appearing as we expand the extension's target platforms. The pattern is consistent: APIs that work perfectly on desktop Chrome fail silently on mobile. `chrome.runtime.sendMessage` returning undefined. `input.click()` being blocked. Auto-opening tabs failing. Each fix is straightforward once diagnosed, but the diagnosis requires knowing which Android restriction is in play.

The `type="button"` addition to the remove button is a small but important detail — inside a `<label>`, buttons without explicit type default to `type="submit"` in some contexts, which could cause unexpected behavior. Always explicit.

## Lessons Learned

1. On Android, `input.click()` via JS is blocked as an indirect gesture. Use `<label for="inputId">` to let the browser handle file picker activation natively.
2. When converting a `<div>` to `<label>`, buttons inside must have `type="button"` explicitly to avoid unintended form behavior.
3. Extensions should not open tabs eagerly on load — lazy initialization (open only when needed) works across all platforms and avoids startup crashes on mobile browsers like Quetta.
