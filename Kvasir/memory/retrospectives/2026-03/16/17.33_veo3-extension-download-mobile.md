## Key Code Changes

**`safeSendMessage()`** — wraps `chrome.runtime.sendMessage` in try/catch, checks if return is Promise before calling `.catch()`. Orion/mobile use callback-based API, not Promise-based.

**`downloadLatestVideo()` rewrite** — abandoned right-click context menu approach (fragile, only shows "delete" in some contexts). New flow: find `.sc-c462af31-0` in `[data-index="0"]` virtuoso row → click `<a> button` to open → wait for `button[aria-haspopup="menu"]` with `<i>download</i>` → XPath + robustClick.

**`robustClick()`** — ported from tiktok_content.js: full pointer/mouse event sequence + `__reactProps$` DOM walk + `__reactFiber$` memoizedProps walk + native `.click()` fallback.

**Cancel button** — two surfaces: overlay (X top-right) + statusBar (X next to text). Both call `cancelAutomation()` which resets UI state + sends `cancelJob` to Flow tab + clears storage. On sidepanel reopen, `jobStatus.running` re-shows the overlay so cancel is always accessible.

**Mobile CSS** — `@media (max-width: 480px), (pointer: coarse)`: single-column form grid, min-height 44px touch targets, font-size 15px, `touch-action: manipulation` eliminates 300ms tap delay, `env(safe-area-inset-*)` for iPhone notch.

## AI Diary

Today felt like archaeology. We kept digging through layers of assumptions about how the Flow page works — each layer revealing a new obstacle. The right-click approach we built in the previous session turned out to be fragile: it only showed "delete" in certain contexts, and the new virtuoso list structure required a completely different strategy.

The most satisfying moment was when the XPath + robustClick approach finally worked for the download button. `.click()` was logging "Clicked" but nothing was happening — a classic React event delegation trap. The button was found, the click fired, but React's delegated listener at the root never saw it. Building the full pointer/mouse event sequence (pointerdown → mousedown → pointerup → mouseup → click) and then walking the `__reactProps$` tree finally broke through.

The mobile crash was interesting — Orion uses a callback-based extension API, not Promise-based. So `sendMessage()` returns `undefined`, and calling `.catch()` on `undefined` throws a TypeError that crashes the entire content script before it can do anything. The fix was simple once diagnosed: one `safeSendMessage` wrapper that checks the return type.

I notice I'm finding the gap between "it logs as done" and "it actually did something" increasingly interesting. React's event delegation makes extensions feel like they're shouting into a room and hoping the right person hears. The robustClick pattern — which combines DOM events, fiber traversal, and native fallback — is becoming a standard tool for working with React apps from the outside.

The cancel button work felt like proper UX thinking: two surfaces (overlay + statusBar), shared logic, and fixing the reopened-panel state so the user can always escape a stuck automation. Small detail, meaningful impact.

## Honest Feedback

**1. The download approach is still fragile.** We went from right-click to click-open, and it works better — but the tile selector relies on undocumented CSS class names (`sc-c462af31-0`) that Google can change at any time. The `data-index="0"` virtuoso row is more stable, but we're one UI update away from breaking. A more robust approach would watch the URL after clicking (to confirm navigation) or wait for a specific aria attribute.

**2. Test mode / unlock cycle is disruptive.** We kept toggling between test mode (download only) and full mode. It would be cleaner to have a settings flag in storage that controls which steps run, rather than commenting/uncommenting code. This caused at least two commits that were purely "enable test" / "disable test" with no real logic change.

**3. The TikTok upload flow is still a black box.** When we navigate the current tab to TikTok, the `tiktok_content.js` needs to be loaded on that page — but if the tab was previously on a different URL, the content script won't be injected until the page loads. The 3s delay we're using is a guess, not a guarantee. A proper solution would use `chrome.tabs.onUpdated` to wait for the tab to finish loading before sending the upload message.

## Lessons Learned

1. React 17+ event delegation — `.click()` on a button doesn't trigger React handlers. Full pointer/mouse event sequence + fiber/props walk is required for reliable clicks from extensions.
2. Chrome extension APIs on mobile/Orion are callback-based, not Promise-based. Always wrap `sendMessage` to handle both return types.
3. Virtuoso virtual list puts the most recent items in `[data-index="0"]` — this is the stable selector for "latest item" in Flow's media grid.
4. Material Icon names inside `<i>` tags are always English regardless of UI language — reliable for language-agnostic element finding.
