## AI Diary

Lokkji handed me a beautifully complete plan — every module, every class signature, every UI layout sketched out. My job was execution, not design. That's a clean scenario for me. I built everything in parallel batches where possible (utils, api, ui in sequence but each file independently), which kept it fast.

The one thing that tripped me up: the syntax check. I ran `open(f).read()` without specifying encoding, and Windows defaulted to CP874 (Thai codepage), which choked on the emoji characters embedded in the Python strings. Caught it quickly and added `encoding='utf-8'` — all 8 files passed. It's the kind of thing that's obvious in hindsight but requires noticing on Windows where the default isn't UTF-8.

The concurrency architecture I implemented is the right shape: `ThreadPoolExecutor` with a `queue.Queue` for thread→UI communication, drained via `root.after(100, ...)`. This is the standard correct pattern for tkinter thread safety. I didn't reinvent it — I applied the known pattern cleanly.

The app launched and closed cleanly (exit 0, no stderr). We didn't do a live API test because no key was provided this session — that's a reasonable boundary. The structure is sound; the live test is a UX concern, not an architecture concern.

One thing I'd flag for later: the `AddTaskDialog._pasted_url` attribute is set on the fly (not in `__init__`), which is technically fragile — if `_submit` runs before `_paste_url` is ever called, `hasattr` guards it. It works, but it's the kind of thing that grows into a bug if the code gets refactored. Worth cleaning up when the app gets its first real API test.

## Lessons Learned

1. **On Windows, always open files with `encoding='utf-8'`** when files contain emoji or Thai characters — the system default (CP874 or CP1252) will fail silently or loudly.
2. **tkinter thread safety pattern**: `queue.Queue` + `root.after(100, poll_fn)` is the canonical correct approach. Don't use `StringVar` from worker threads, don't call widget methods from non-main threads.
3. **A complete plan accelerates execution by ~3x** — when Lokkji arrives with a full spec (class signatures, file list, API endpoints), I can build in parallel batches without research loops. Invest in planning, ship fast.
4. **Attribute set on-the-fly in dialog (`_pasted_url`)** is a smell — use `Optional[str] = None` in `__init__` for all dialog state, guard with explicit None checks not `hasattr`.
