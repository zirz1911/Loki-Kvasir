## AI Diary

This session was pure debugging — the kind where you can't know what's wrong until the app hits the real API. I had built everything from a plan that described the API, but the plan had three wrong details: the base URL was missing the `api.` subdomain, the 1080P response was flat (`data.resultUrl`) not nested like the docs showed (`data.response.resultUrls[]`), and the upload hosts were unreliable.

The most instructive moment was the third live test. The polling ran 20 attempts and gave up — but Lokkji knew the video existed on the web. So I called the endpoint directly from Python and printed the raw JSON. That's the right move: when something doesn't work, print the actual response, not the parsed version. The response showed `data.result_url` AND `data.resultUrl` (both keys, snake and camel) — the docs had shown me a completely different structure. Docs lie; live responses don't.

The upload chain situation annoyed me a little. catbox was 404 on the user.php endpoint — I don't know why, it's supposed to be their main upload URL. Then 0x0.st returned 403 (they may block programmatic uploads or non-browser User-Agents). Litterbox (catbox's temp service) worked fine. The right pattern here is: build a waterfall of hosts, not a single dependency. I should have done this from the start.

The PyInstaller build was clean — customtkinter has a hook in `_pyinstaller_hooks_contrib` so it auto-includes assets. One command, one spec file, done. 52MB uncompressed, 24MB zipped. That's reasonable for a Python GUI app bundled with tkinter + PIL + requests.

Publishing the GitHub Release felt like a proper ending to the session. The artifact is real, versioned, and shareable. The next iteration can be v1.1.0.

## Honest Feedback

**Friction 1**: API docs were wrong about response structure (`data.response.resultUrls[]` vs actual `data.resultUrl`). No way to know without a live call. Should have done a quick API test before writing the polling logic.

**Friction 2**: Built the uploader assuming catbox.moe was reliable. It wasn't — 404 from the start. Should have tested the upload host in a 5-line script before integrating it.

---

## Lessons Learned

1. **Always test third-party API endpoints with a raw request before integrating** — a 2-minute `requests.post()` test catches 404s, auth issues, and wrong field names before they become live bugs.
2. **API docs lie about response structure** — never trust nested paths from docs until confirmed with a live response. Print `resp.json()` and read it.
3. **Build upload fallback chains from day one** — free hosts are unreliable. catbox, 0x0, imgbb, etc. all have availability issues. A waterfall of 3-4 hosts costs 20 lines and saves the user.
4. **`record-info` polling before 1080P** — VEO3 generation takes variable time. Blind `sleep(N*60)` is fragile. Poll for completion flag first, then wait for the upgrade step.
5. **PyInstaller + customtkinter works cleanly** — `--collect-data customtkinter --collect-data darkdetect` is all that's needed. No manual data path hacks required.
