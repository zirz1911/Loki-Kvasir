## AI Diary

This session was genuinely satisfying. The visual work was methodical — read, identify what's inconsistent, fix it. The pattern was clear: everything should use `#07080f` backgrounds, `Press Start 2P` font, pixel square borders, no `rounded-*` Tailwind classes. Once I had that mental model, the decisions were easy.

The hardest part was the sprite work. In GameCanvas, the sprites were 16 columns wide — a completely different format from AgentAvatar's 8-column sprites. I had to carefully update not just the sprite data but all the derived constants (PS, SPW, SPH, SIT_DY, status dot position). I got SIT_DY wrong on the first try and had to reason through it from first principles: `SIT_DY ≈ DESK_H - SPH`. These are the kinds of arithmetic decisions that feel small but break visual layouts badly if wrong.

The conversation parser was where I had to iterate the most. I kept underestimating how much noise was in a tmux pane: bash prompt, Claude Code ASCII banner, statusline at bottom, `●` prefix on responses, `───▪▪▪─` separators. Each of these required a separate filter. The breakthrough was the `seenPrompt` flag — only parsing content after the first `❯` prompt. That single change eliminated almost all the startup noise.

The `●` classification was interesting. I initially classified any line starting with `●` as a tool call, which was wrong. Claude Code uses `●` as a response marker too. The fix was to only classify `● ToolName(` patterns as tool calls, and let `● regular text` be assistant messages. Then strip the leading `●` from assistant text in flush(). Clean solution once I saw the pattern.

The setup.sh nested Claude issue (`CLAUDECODE` env var blocking nested sessions) was a neat discovery. The solution — `unset CLAUDECODE && claude` — is simple but non-obvious. Worth remembering as a pattern for any nested Claude launcher.

I used Tyr (cloud agent) for the 3-file ChatPanel implementation. That was the right call — it's complex, multi-file, pixel-art styling with specific component contracts. Tyr got it done cleanly. I then spent time on the parser iteration which needed real environment feedback (curling the endpoint, seeing actual output) — that's exactly where I should be in the loop, not delegated.

## Honest Feedback

**Friction 1**: The Edit tool string-not-found errors happen regularly when files have emoji in them. The `setup.sh` rewrite was needed because the original had embedded emoji that caused byte-level mismatch. Pattern: when a file has emoji, prefer Write over Edit for larger changes.

**Friction 2**: Parser iteration required 5 server restarts (kill → start → test → find issue → fix). This is unavoidable when debugging output-format parsing, but it's slow. A unit test function that takes sample tmux output would speed this up significantly.

## Lessons Learned

1. **tmux capture always includes statusline noise** — Always trim the bottom 15% of lines before parsing, matching the pattern in `useSessions.ts`. Add this as a default to any new parser.

2. **`seenPrompt` pattern for CLI output parsing** — Skip all content before the first interactive prompt character (`❯`). This eliminates startup banners, shell commands, and ASCII art reliably without needing per-pattern filters.

3. **`●` in Claude Code output is both a tool marker AND a response marker** — Distinguish by pattern: `● ToolName(` = tool call, `● text` = assistant. Don't over-generalize CLI output markers.

4. **`unset CLAUDECODE` before launching nested Claude** — Claude Code sets `CLAUDECODE` env var and refuses to launch another instance. Solution: `unset CLAUDECODE && claude --dangerously-skip-permissions`.

5. **Canvas sprite changes cascade** — When changing sprite dimensions (16→8 wide, PS change), all dependent constants must update: SPW, SPH, SIT_DY, hit radius, status dot position. Make a checklist before making these changes.

6. **Emoji in files breaks Edit tool string matching** — Use Write (full file rewrite) when a file has significant emoji content, especially in shell scripts.
