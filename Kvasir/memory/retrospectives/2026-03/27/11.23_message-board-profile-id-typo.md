## AI Diary

This was a one-diagnosis session. The user said "กดเปลี่ยนเบอร์แต่ Workflow Automation ไม่ทำงาน" and within two reads — server.js and config.json — the answer was there. `RFCY60256MV` vs `RFCY602S6MV`. The digit 5 standing in for the letter S. Classic visual confusion: on a small input field, `5` and `S` are adjacent on the keyboard and similar in shape. The admin panel has no validation on profile_id format because there's no canonical format to validate against — it's just a GemLogin-assigned string. So the typo passed silently all the way to the webhook, which then sent a request with a nonexistent profile_id.

What made this diagnosable quickly was that config.json was the single source of truth after the refactor. Before the admin panel refactor, CARDS were duplicated across server.js and index.html — finding a typo there would have meant checking two places. Now there's one file, one place to look. The refactor paid off immediately on the first real data entry bug.

I also noticed the admin panel was built entirely between sessions — the user built it independently, committed it, and I arrived to find it already done. That's the second time this has happened (email board was the first). The pattern is: user builds a self-contained feature solo, then comes back when something's wrong with data they entered through it. My role shifts from builder to debugger.

## Honest Feedback

**1. Admin panel has no profile_id format hint.** The input field accepts any string. A placeholder showing the expected format (`e.g. RFCY602S6MV`) or a note about case-sensitivity would reduce typo risk. The `S`/`5` confusion is predictable on any keyboard or phone input.

**2. config.json is gitignored but has no backup/export in admin panel.** If the server machine is lost or config.json is accidentally deleted, all card configurations are gone. The admin panel could offer a JSON export button. Low priority but worth noting.

**3. No feedback in admin panel when webhook fails.** After fixing the profile_id and firing swap, the admin panel presumably shows success (the server returns 200 from `fireWebhook`). But GemLogin could silently fail if profile_id doesn't exist — the server doesn't check the response body. A user would only notice the workflow didn't run, not why.

## Lessons Learned

- Single source of truth (config.json) makes typo diagnosis faster — found the bug in one file instead of two
- `S`/`5` visual confusion is predictable in profile_id fields — placeholder text with format example would prevent it

## Next Steps
