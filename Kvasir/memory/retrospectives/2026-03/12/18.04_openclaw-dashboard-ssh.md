**runCommand non-zero exit fix** — execSync throws but stdout still has data:
```typescript
catch (err: any) {
  const out = err?.stdout ?? err?.output?.[1] ?? ""
  return out ? String(out).trim() : fallback
}
```


## Honest Feedback

**Friction 1 — iOS zoom required two tries**: I should have added both `maximum-scale=1.0` AND `user-scalable=no` on the first attempt. I know this is the correct pattern for preventing iOS input-focus zoom. The first fix was incomplete. Cost: one round-trip.

**Friction 2 — SSH assumed standard PATH**: When I built the SSH instance, I assumed `openclaw` would be in the default PATH. It wasn't — it was in Ubuntu proot. I should have noted upfront that on Android/Termux setups, `openclaw` is typically inside proot-distro, and asked whether to add proot wrapping before testing. Instead we debugged it reactively.

**Friction 3 — execSync exit code behavior**: I built `runCommand` assuming successful exit = has output. But `openclaw health` on a machine where the gateway is already running outputs meaningful data AND exits non-zero (due to gateway conflict messages). I should have used a pattern that captures stdout regardless of exit code from the start, since health check commands commonly print useful info even when something is "wrong".

## Lessons Learned

1. iOS input zoom requires BOTH `maximum-scale=1.0` AND `user-scalable=no` — either alone is insufficient
2. `execSync` throws on non-zero exit but `err.stdout` still contains the output — always capture it
3. Android/Termux openclaw is inside Ubuntu proot — SSH commands need `proot-distro login ubuntu --` prefix
4. Adding `sshCommand` as an override field is the right pattern for instance-specific remote invocations
