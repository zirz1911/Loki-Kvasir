## AI Diary

The pulse not working was a three-layer bug. I found the first layer (React state setter purity) in the previous context — calling `extendSaiyan` inside `setCaptureData(p => {...})` which React can call multiple times as a pure function. That was real. But fixing it wasn't enough.

The second layer surprised me: the `#office` route in App.tsx simply never forwarded `saiyanTargets` to `PixelOfficeView`, and `PixelOfficeView` never forwarded it to `DepartmentRoom`. The whole prop chain was missing. When you're building incrementally, it's easy to wire up saiyan in MissionControl and GameCanvas and Fleet but forget the original office view. Classic "I added the feature to the new stuff but forgot the old stuff."

The third layer was the spinner detection. I assumed `✢ Spelunking` would be in the bottom 5 non-empty lines. But Claude Code's terminal has a status bar taking the bottom 4 lines (separator, `❯`, separator, context info, bypass line) — so the spinner is actually at position 6-10 from bottom depending on tip text. bottom15 catches it reliably. I also realized I only added `Spelunking|thinking|Running` as text patterns but Claude Code uses many different words: Billowing, Actioning, Drizzling, Spelunking... I should have used a more general pattern like `… \(\d` or just rely on the `● ToolName(` pattern which is more stable.

The global hooks issue was the biggest architectural miss. Hooks in `settings.local.json` only fire for that project's sessions. Lokkji's Claude sessions when working on Loki-Pixfice or other projects never triggered feed events. The feed infrastructure was there but only half-connected. Fixing this by adding to `~/.claude/settings.json` should make every session contribute to the feed now.

The responsive pass went smoothly thanks to delegating audit (Explore agent) then fixing (Tyr agent). The audit was thorough — 340px grid minimum was genuinely broken on phones. Tyr handled the mechanical refactoring well. I appreciated that ChatPanel was already correct (isMobile → 100% width was already implemented) — that saved time.

One thing I keep doing: not testing live in browser after changes. I trust the build output and server restart but don't actually visually confirm. That's fine for mechanical fixes but risky for animation/visual work.

## Lessons Learned

1. **Always trace prop chains end-to-end before debugging logic.** When a visual feature isn't working, first check: does the data even reach the component? The saiyan pulse was never wired to #office — all the logic was correct, just never connected.

2. **Claude Code's terminal has a fixed 4-5 line status bar at the bottom.** Any bottom-N line check for spinner activity needs N≥10 to clear the status bar reliably. bottom5 is too narrow.

3. **Text pattern matching against Claude Code spinner words is fragile.** The thinking words rotate (Spelunking/Billowing/Actioning/Drizzling/etc). Prefer structural patterns: `● \w+\(` (tool call), or the duration format `\(\d+s`, or rely on hash-change detection.

4. **Project-level hooks (settings.local.json) don't fire in other projects.** If you want system-wide feed events, put hooks in `~/.claude/settings.json`. This is the right place for cross-project monitoring infrastructure.

5. **React state updater functions must be pure.** Side effects (sounds, timers, external state) called inside `setState(prev => {...})` are incorrect — React may call updaters multiple times in StrictMode or concurrent features. Always track derived state in refs and call side effects in the enclosing function scope.
