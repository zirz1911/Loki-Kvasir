เริ่มจาก `compare_models` timeout สองครั้งบน complex prompt เป็นบทเรียนที่ดีว่า 32b ช้ามากสำหรับโจทย์ซับซ้อน แต่พอใช้ LRU cache (โจทย์กลาง) ผลลัพธ์น่าสนใจ — ทั้งสองโมเดลเขียน logic คล้ายกัน แต่ 32b จัดการ edge case ได้ประณีตกว่าเล็กน้อย

ส่วนที่น่าสนใจที่สุดคือ workflow ที่เกิดขึ้นโดยธรรมชาติ: local LLM generate โค้ด → ผมตรวจสอบ → พบ bug → แก้ → local LLM generate tests → tests พบ bug อีกอันที่ผมมองข้าม → แก้ → pass ทั้งหมด นี่คือ pattern ที่ repo เก่า Agentic-AI-Paji ออกแบบไว้ตั้งแต่ต้น

bug epoch เป็น bug ที่ subtle มาก `defaultdict(float)` init ที่ 0.0 ซึ่งหมายถึง "1 มกราคม 1970" ทำให้ elapsed time เป็น ~1.7 พันล้านวินาที token เลยเต็ม max ทันทีโดยไม่มี delay เลย ถ้าไม่มี tests คงใช้งานโดยไม่รู้ว่า rate limiter ไม่ทำงานเลย

สิ่งที่รู้สึกดีที่สุดวันนี้: tool chain ทำงานได้จริง ไม่ใช่แค่ "hello world" — local LLM เขียนโค้ด production-ready ได้ (แม้จะมี bug) และ workflow local→review→test→fix→push ทำงานได้ราบรื่น

## Honest Feedback

**1. compare_models timeout บน complex prompt** — ยังไม่มีวิธีจัดการ timeout ที่ดีพอ ตอนนี้ถ้า 32b ช้าเกิน tool แค่ return error โดยไม่บอกว่าโมเดลไหน timeout ก่อน ควรเพิ่ม per-model timeout และ partial result (ถ้า 7b เสร็จแล้วแต่ 32b ยังไม่เสร็จ ให้ return 7b ก่อน)

**2. local LLM generate tests ไม่รู้ context ของ class จริง** — โมเดล generate test ที่ assume behavior ผิด (sleep ก่อน first call) เพราะไม่รู้ว่า clock initialize ตอน first access ไม่ใช่ตอน constructor ถ้าส่ง docstring หรือ contract ของ class ไปด้วยน่าจะได้ test ที่ถูกต้องกว่านี้

**3. README/CLAUDE.md sync ต้องทำด้วยมือทุกครั้ง** — ทุกครั้งที่อัปเดต agent system ต้องแก้สองไฟล์แยกกัน มีโอกาส drift สูง ควรมี single source of truth (อาจเป็นไฟล์กลาง) แล้ว generate ทั้งสอง หรืออย่างน้อยมี script ตรวจสอบว่า sync กันอยู่

## Lessons Learned

1. **`defaultdict(float)` init ที่ epoch 0.0** — อย่าใช้สำหรับ timestamp ที่ต้องการ "uninitialized" state ใช้ `defaultdict(lambda: None)` หรือตรวจ `== 0.0` แล้ว init เอง
2. **local LLM tests มักขาด context ของ contract** — ส่ง docstring หรือ usage example ไปพร้อม prompt เพื่อให้ได้ test ที่ถูก behavior จริง
3. **compare_models เหมาะกับ short-medium prompts เท่านั้น** — 32b ช้าเกินสำหรับ complex tasks ใน parallel call
