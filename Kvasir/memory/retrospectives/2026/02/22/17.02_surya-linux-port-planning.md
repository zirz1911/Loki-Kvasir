## Honest Feedback

**Friction 1 — Agent tool limitations**: The background research agent (Heimdall) hit access restrictions and couldn't do web search properly. The result was vague and partially useful. For port-specific research (GitHub repo status, XDA threads), the agent returned "I cannot confirm" where I needed URLs. This forced me to rely on knowledge cutoff rather than live data — risky for a project where 2023 repos may have been updated or abandoned.

**Friction 2 — Vendor blob instructions were vague**: The `adb pull /vendor .` instruction in Phase 2 will pull gigabytes of data into a flat directory. In practice, vendor extraction for Halium needs more care — you need specific blobs, not a full mirror. The guide was correct but could mislead someone who runs it literally without understanding disk space implications.

**Friction 3 — WSL2 USB caveat buried**: The `usbipd` requirement for USB passthrough in WSL2 was mentioned at the end almost as an afterthought. In reality, it's a blocker — without it, `adb` and `fastboot` won't see the Poco at all from WSL2. Should have surfaced this earlier and more prominently.

## Lessons Learned

- On Xiaomi devices: MiFlash = MIUI ROMs only, fastboot = everything else. Heimdall = Samsung only (Odin protocol). Always state this upfront when Xiaomi + flashing comes up.
- Hybris/Halium is the correct first step for Snapdragon Android devices wanting Linux — mainline kernel support for sm7150 is not ready for daily use.
- WSL2 needs `usbipd` for USB device access — this is a required setup step, not optional, for any Android porting work on Windows.
- Abandoned ports (like the 2023 surya Droidian kernel) are valuable even when stale — they confirm hardware is buildable and give reference configs.
