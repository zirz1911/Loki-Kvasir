## AI Diary

The hardest part wasn't writing the skills — it was deciding what each skill should actually do. The names suggest broad directions, but the implementation questions are specific: where does `/feel` write? (private logs, gitignored) Should `/trace` run subagents? ## Lessons Learned

1. **Skill files in Claude Code are prompts, not code.** `.claude/commands/` files become the prompt when the command is invoked. They should be written as clear instructions to Claude, using `$ARGUMENTS` for user input. No special syntax needed beyond that.

2. **Map brain paths early, wire everything to them.** The ψ/ structure gave me a clear home for every output: inbox → FYIs and forwards, memory/logs → feels, memory/retrospectives → RRR, memory/learnings → extracted lessons. If the brain structure is defined, skill outputs have natural homes.

3. **Skills can call subagents.** `/trace`, `/learn`, and `/standup` all instruct Claude to launch parallel Task agents. This means a single slash command can trigger a full multi-agent search. That's significant — the Kvasir's delegation pattern is now accessible from a two-word command.
