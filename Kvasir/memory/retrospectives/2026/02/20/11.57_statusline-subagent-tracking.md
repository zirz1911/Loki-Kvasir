## AI Diary

This session had a satisfying arc — two clean features, then a bug hunt that revealed something genuinely interesting about Windows path handling.

The WorldMap auto-refresh was straightforward. DataRefreshContext follows the exact same pattern as TimezoneContext — a Provider, a custom hook, a countdown. The UI addition is clean: `● LIVE · ↻ 4:59` next to each panel header, clickable to force refresh. Twenty minutes of work, tested mentally against the architecture, no surprises.

Then came the statusline work, which I'd been thinking about in the background. The icon spacing was trivial — change `"⚡Thor"` to `("⚡", "Thor")` and render with a space. But the subagent tracking problem was more interesting.

The architecture I designed: PreToolUse writes the active agent name to a temp file, statusline reads it on every poll, PostToolUse clears it. Elegant in theory. In practice, two bugs surfaced.

First bug: `async: true`. I assumed async hooks would write the file before the tool completes. Wrong — async means the Python process starts IN PARALLEL with the tool, not before it. On Windows, Python startup takes ~300ms. Fast local LLM tools complete in under a second. The Python process might never write the file before PostToolUse fires. Fix: make hooks synchronous. Simple once identified.

Second bug: the path. I wrote `D:\\Loki-Kvasir\\Loki-Kvasir\\.claude\\subagent_tracker.py` in JSON. That represents `D:\Loki-Kvasir\Loki-Kvasir\.claude\subagent_tracker.py`. When Windows CMD (or whatever Claude Code uses to invoke hooks) processes this, the `\.` combination — backslash followed by dot — gets stripped. The result is all path components after the second level get concatenated: `Loki-KvasirLoki-Kvasir.claudesubagent_tracker.py`. A completely mangled filename.

The fix was immediately obvious once I saw it: the statusline command already uses forward slashes (`D:/Loki-Kvasir/Loki-Kvasir/.claude/statusline.py`) and works perfectly. Switch to forward slashes. Done. Why do forward slashes work? Because Python and Windows both accept them, and no shell interpretation strips them.

The lesson burns: **dot-prefixed directories with backslashes are a trap on Windows**. `.claude`, `.git`, `.next` — any hidden-Unix-style directory accessed via backslash path in CMD context is at risk. Always use forward slashes when the path contains a dot-prefixed directory.

What makes me reflect on this: I've hit the `D:\` traversal issue before (previous sessions). I remembered it and used PowerShell. But this new variant — backslash + dot-prefix directory mangling — was new territory. Filed and documented.

## Lessons Learned

1. **Windows: backslash + dot-prefix dir = path mangling in hook commands.** `\.claude\` gets stripped. Use forward slashes: `/.claude/`. This applies to any dot-prefixed directory (`.claude`, `.git`, `.next`) when invoked via Claude Code hook commands.

2. **Hook async vs sync matters for timing-sensitive signals.** `async: true` = hook runs in parallel, not before. For signals that must precede tool execution (like statusline updates), hooks must be synchronous (no `async` flag or `async: false`).

3. **Copy-paste hook patterns without reasoning = wrong assumptions.** Voice hook is async because speech-after is fine. Statusline tracker is sync because timing-before/after is critical. Always reason about the timing requirement before choosing async.
