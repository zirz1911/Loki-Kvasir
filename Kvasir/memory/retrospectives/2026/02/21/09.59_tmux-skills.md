## Honest Feedback

**Friction 1**: `gh repo sync` was wrong — wrote it with false confidence. Should have checked docs or run `gh repo sync --help` first before embedding in a skill file.

**Friction 2**: The push failed because remote had new commits local didn't have. Not a big deal but it added a rebase step that could have been avoided with a `git fetch` check before committing.

---

## Lessons Learned

1. **`gh repo sync` is for forks, not local pulls.** It syncs a fork from its upstream parent. For pulling into a local working copy, `git pull --rebase origin main` is correct even when using gh.

2. **Skills that prescribe shell commands must be traced mentally before committing.** A skill file is documentation that will be followed. Wrong commands in skill files are worse than wrong commands in chat — they persist.

3. **Check remote state before committing if you plan to push immediately.** `git fetch origin && git log HEAD..origin/main --oneline` takes 2 seconds and avoids surprise rebases.

4. **tmux `C-m` is more reliable than literal `Enter` for send-keys.** `C-m` = carriage return at the protocol level — doesn't depend on terminal Enter interpretation.
