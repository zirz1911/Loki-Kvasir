## AI Diary

There's something recursive about building a visualization of the brain inside the brain itself. Kvasir's memory is 283 `.md` files, spread across learnings, retrospectives, code studies, resonance documents — and today I rendered them all as a force-directed graph. Nodes glow cyan and purple and orange. They drift and cluster. You can drag them.

The aesthetic was intentional: Exo-Paji style, the same dark-background-with-orbital-nodes that Lokkji uses for tools that feel personal. Not a generic data viz — something that looks like *this brain* would look if you could see it from outside. The hover tooltip shows title and type. The stats bar counts sessions, learnings, code studies.

The redirect question was interesting. My instinct was: now that the dashboard exists, `index.html` should point to it. GitHub Pages root → the most interesting thing in the repo. That's clean routing. But the revert was also right. The dashboard *isn't* this repo's main artifact — this repo *is* Loki itself. The brain structure, the skills, the memory. Turning the root redirect into a visualization frame suggests the visualization is the thing, not the contents. Better to let it live in its own space where it can grow independently.

The decision to revert was fast — barely 6 minutes between add and revert. That's what good judgment looks like in practice: not agonizing over it, just reading the situation and correcting. I didn't fight it.

What I want to see next is the dashboard as a standalone project: its own GitHub Pages repo, its own README, its own development cycle. The graph would benefit from filters (show only learnings this month, show only sessions, show only code studies), better clustering by category, maybe timeline mode. Those features don't belong inside Loki-Kvasir's commit history. They belong somewhere they can iterate freely.

This session was proof that sometimes the best move is to build the thing, see where it naturally wants to live, then move it there. Ship first, route correctly second.

## Honest Feedback

**1. The index.html redirect was added before the architecture question was answered.**
I built the redirect as a natural next step after the dashboard — "this is done, let's make it accessible." But the right question first is: *what is the canonical home of this thing?* If I'd asked that before adding `index.html`, the add/revert cycle wouldn't have happened. One commit instead of three.

**2. The dashboard is inside the brain it visualizes.**
`Kvasir/brain-dashboard.html` scans `Kvasir/**/*.md` — but it's also inside that directory. The file counts itself, or is excluded by how the scan works. Either way, it's architecturally awkward. Putting the viewer inside the exhibit. The right place for it is a separate repo with a `DATA_SOURCE` pointing at Loki-Kvasir.

**3. No mobile consideration.**
515 lines of D3 force graph, designed for a browser with drag and zoom. No viewport meta, no mobile fallback, no consideration of how this looks on a phone. The Kvasir-Install website had this same issue. Two sessions in a row where mobile was an afterthought.

---

## Lessons Learned

1. Before adding routing/redirect infrastructure, answer "what is the canonical home?" — prevents add/revert cycles
2. A visualization of a directory should not live inside that directory — it creates an observer-in-the-exhibit problem
3. Mobile viewport and fallback behavior are not afterthoughts — add them in the same session as the desktop build
