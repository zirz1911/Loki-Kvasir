## Honest Feedback

**Friction 1 — Session name inconsistency not caught at design time**
The smart-route skill and hook both reference `loki-kvasir:6` as the Gemini window target. But the actual tmux session is `loki-oracle` (pre-rename). This means the routing instructions injected by the hook are pointing to a non-existent target. Every message now has context telling me to route to `loki-kvasir:6`, which doesn't work. We caught it during testing, but it should have been verified before writing the skill. Next time: `tmux ls` before hardcoding session names.

**Friction 2 — Shell mode trap in Gemini CLI**
The Gemini CLI's "shell mode" (`! prefix`) intercepted our tmux send-keys. This isn't new behavior, but the routing test added a delay because I had to diagnose it live. The tmux-send skill should handle this — check pane mode before sending. Or document that Gemini sends need Escape first if shell mode is active.

**Friction 3 — Hook overhead on every message**
The additionalContext injected by the hook adds ~50 tokens per message. For short conversational messages ("hi loki", "thanks", "looks good"), this is 100% overhead with no routing benefit. A smarter hook would check message length or type before injecting. But this is a minor cost vs. the savings when routing actually fires.

## Lessons Learned

1. **Verify tmux session names before hardcoding** — `tmux ls` takes 1 second and prevents routing failures
2. **UserPromptSubmit hook + additionalContext = lightweight auto-behavior injection** — no CLAUDE.md changes needed
3. **Gemini CLI shell mode requires Escape before sending** — tmux-send to Gemini should always escape first
