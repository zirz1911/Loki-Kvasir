## Honest Feedback

**1. Token ใน URL เป็น anti-pattern**
ก่อน credential store ถูก setup token โผล่ใน git remote URL แบบ plain text (`git remote -v` จะเห็นทันที) ถ้า user รัน `git remote -v` ก่อน setup store token จะ leak ใน terminal history ควรแนะนำ credential store ก่อนเป็นขั้นตอนแรก ไม่ใช่ทีหลัง

**2. ไม่ได้ตรวจว่า Forgejo repo ถูกสร้างแล้วหรือยัง**
Push ครั้งแรกสำเร็จแบบ `[new branch]` ซึ่งแปลว่า repo ถูกสร้างไว้แล้วบน Forgejo ก่อนหน้านี้ แต่ไม่ได้ถามว่าสร้างแล้วหรือยัง ถ้ายังไม่มี repo จะ error ไม่ได้ guide ขั้นตอน create repo ก่อน push

**3. ไม่ได้ตั้ง upstream**
`git push forgejo main` สำเร็จ แต่ไม่ได้ทำ `git push -u forgejo main` เลย `git status` จะไม่บอกว่า forgejo ล้าหลัง/นำหน้ากี่ commit การ track upstream ทั้งสอง remote พร้อมกันจะ useful มาก

## Lessons Learned

1. **Forgejo auth ใน non-TTY environment ต้องใช้ credential store หรือ token-in-URL** — terminal ไม่มี stdin สำหรับ interactive password prompt
2. **`git remote add` + `push` = สองขั้นตอนเท่านั้น** สำหรับ mirror repo ไปยัง self-hosted Git
3. **เก็บ token ใน `~/.git-credentials` ด้วย `credential.helper store`** แทนการ hardcode ใน remote URL
