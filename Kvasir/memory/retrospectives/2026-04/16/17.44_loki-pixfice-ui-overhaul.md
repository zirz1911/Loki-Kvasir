## Honest Feedback

**Friction 1: Build cycle ทุกครั้งที่ต้องเห็นผล**
session นี้ build+restart 8+ ครั้ง แต่ละรอบ ~2 วินาที — ไม่ช้า แต่ interrupt flow ถ้ามี HMR (Hot Module Replacement) ที่ทำงานกับ Bun server จะดีกว่ามาก ปัญหาคือ `loki-office-dev` (vite dev server) ถูก stop ไว้ และการ run พร้อมกับ pm2 backend ต้องการ port coordination ที่ซับซ้อน

**Friction 2: `overflow: hidden` เป็น trap ที่ซ่อนตัว**
ใน CSS hierarchy ที่ลึก การมี `overflow: hidden` ที่ ancestor ตัวเดียวตัดความสามารถ scroll ของ descendant ทั้งหมด แต่ไม่มี visual indicator ให้รู้ว่ามีอยู่ที่ไหน ต้อง inspect ทีละชั้นด้วยมือ ถ้า DevTools เปิดตลอดอาจจะเร็วกว่า แต่ session นี้ทำผ่าน remote เลยต้อง reason ด้วย code เท่านั้น

**Friction 3: Avatar size ที่เล็กมากกับ 5×5 grid**
ที่ size 20px (ใน RoomsView เดิม) pixel แต่ละอันได้ 2px ซึ่งเล็กเกินไปจนแทบมองไม่เห็น pattern ต้องปรับ minimum size เป็น 28px ถึงจะ readable แต่นั่นหมายถึง row height ใน Rooms เพิ่มขึ้นด้วย trade-off ที่ acceptable แต่ต้องตัดสินใจ

## Lessons Learned

1. **CSS scroll trap**: `overflow: hidden` ที่ ancestor ไม่มี visual warning — ต้อง check ทุก wrapper ใน hierarchy เมื่อ scroll ไม่ทำงาน
2. **Canvas char measurement**: `ctx.measureText("M").width` ให้ค่า monospace char width ที่แม่นยำกว่า estimate (0.601 * fontSize) สำหรับ tmux resize calculation
3. **Full-name lookup ก่อน first-word split**: `loki-gemini` ต้อง check full name ก่อน ไม่งั้น inherit parent color โดยไม่ตั้งใจ
4. **Sibling repo as reference**: อ่าน Athena-Office ก่อน implement upload — ได้ pattern ที่ work แล้วทั้ง flow, API shape, และ UX
