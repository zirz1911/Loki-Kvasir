## AI Diary

Three bugs, one root cause: the rename happened but the running state didn't follow.

The zombie process was the most interesting one. A bun server started on Apr06 — ten days ago — from a path that no longer existed. The directory was renamed but the OS kernel kept the process alive because it had the file descriptors open. The process was functionally fine (serving on port 3457) but unreachable for restart. When Lokkji tried to launch the web again, any script pointing to `Athena-Oracle` failed immediately. The fix was simply to kill the old process and restart from the correct path.

The tmux session was simpler: it had never been created in this new context. The old session died when the machine... rebooted? Or was never migrated. `setup-tmux.sh` creates the whole `athena` session with 8 agent windows. One command fixed that entirely.

The keyboard Enter bug was the most satisfying to find. Looking at the keydown handler, pressing Enter sent `inputBuf` (the typed text) via `queueSend`, cleared the buffer, updated the UI — but never sent the actual Enter keystroke (`\r`). So the text would appear typed into tmux but not executed. The web ENTER button worked because `sendKey('\r')` always sent `\r` directly. The fix was one line: `queueSend('\r')` after the buffer send.

What strikes me is how the rename surface area extended far beyond the obvious. Not just `setup-tmux.sh` (which was already updated to use `Athena-Kvasir`). But the long-lived bun process in RAM, the missing tmux session that presumably existed before the rename and restart cycle, and the keyboard bug which is unrelated to the rename but got noticed in this context. One rename, three problems. The lesson isn't "don't rename" — it's "after a rename, check what's *running*, not just what's *written*."

The Athena web office is back. Eight tmux windows, keyboard Enter works, focus indicator shows when the terminal is active. A good debugging session.

## Honest Feedback

**Three friction points:**

1. **No process registry for long-lived servers.** The bun server had been running from a dead path for ten days. There's no mechanism to detect "this process is running from a path that no longer exists." A simple health check script (`systemctl status` or a watchdog that verifies `cwd` matches expected) would catch this immediately. The current setup relies on manual inspection via `ps aux` — which is fine, but fragile. If the server had crashed during those ten days and failed to restart, nobody would know why.

2. **Rename had partial documentation.** The CLAUDE.md, setup-tmux.sh, and package.json were all updated to `Athena-Kvasir`. But there was no "rename checklist" to verify everything was updated: running processes, tmux sessions, systemd services, cloudflared config. The cloudflared config still references `athena-oracle.site` as the domain — this is intentional (it's the domain name, not the repo name) but it could confuse future debugging. A brief rename-audit step in CLAUDE.md or a `post-rename.sh` script would help.

3. **Terminal's `term` div focus model is fragile on mobile.** The keyboard fix (Enter sends `\r`) works perfectly on desktop. But on mobile/touch devices, a `<div tabindex="0">` doesn't reliably open the virtual keyboard. The current key-bar buttons (ESC, TAB, ENTER, arrow keys) are the main interface on mobile — but for typing full commands, mobile users would need a hidden `<input>` element that forwards keystrokes. This hasn't been a pain point yet, but if Lokkji ever accesses Athena from a phone, the terminal input will be read-only.

---

## Lessons Learned

**After a directory rename, check running state — not just written state.**

Scripts and configs update cleanly with find-replace. But long-lived processes, tmux sessions, and background services carry the old identity in RAM. The code says "Kvasir" but the process is still running from "Oracle". Always audit: what's currently running? (`ps aux | grep old-name`), what sessions exist? (`tmux list-sessions`), what ports are bound? (`lsof -i :PORT`).
