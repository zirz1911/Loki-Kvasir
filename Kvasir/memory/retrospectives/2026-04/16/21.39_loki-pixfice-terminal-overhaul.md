## Honest Feedback

**Friction 1: tmux escape sequence debugging เป็น rabbit hole ที่ไม่มีก้น**
ใช้เวลาหลายรอบกว่าจะยอมรับว่าปัญหาอยู่ที่ architecture ไม่ใช่ configuration สัญชาตญาณแรกคือ "แก้ config อีกนิด" แต่ความจริงคือ xterm.js + raw PTY ไม่เหมาะกับ use case นี้ตั้งแต่แรก ควรถามว่า "approach นี้ถูกต้องไหม?" ก่อน แทนที่จะ "fix นี้ยังไง?"

**Friction 2: ย้อนไปมาระหว่าง styles (original pixel-art ↔ Paji-Exo)**
ต้องเปลี่ยนสไตล์ terminal 3-4 รอบ เพราะ user เห็นว่า new style มี visual bugs — ซึ่งที่จริง bugs มาจาก xterm.js ไม่ใช่สไตล์ ถ้าเราแก้ architecture ก่อนแล้วค่อย restyle ก็น่าจะทำครั้งเดียวจบ ลำดับการทำงานสำคัญ: fix foundation ก่อน แล้วค่อย polish

**Friction 3: PM2 EADDRINUSE crash loop ทำให้สับสน**
restart หลายครั้งโดยไม่รู้ว่า server ไม่ได้ up จริง เพราะ port ค้างอยู่ ควร health-check ทุกครั้งหลัง restart — `lsof -ti:3456` ก่อน `pm2 restart` เป็น pattern ที่ควร bake เข้าไป

## Lessons Learned

1. **`tmux capture-pane` > PTY attach สำหรับ web terminal viewer** — clean ANSI text, ไม่มี VT100 cursor sequences, ไม่มี escape garbage, Thai input ทำงานได้ผ่าน `send-keys -l`
2. **`sh -c "...; exec cmd"` ใน PTY stream ทำให้มี shell init noise** — ถ้าต้องการ run command ใน PTY ควร spawn ตรงๆ ไม่ผ่าน shell wrapper
3. **node-pty ต้องการ Node.js event loop** — ถ้าใช้ Bun ต้อง spawn Node.js subprocess แยก, ไม่ใช่แค่ require node-pty ใน Bun context
4. **Fix architecture ก่อน restyle** — visual polish บน broken foundation ทำให้เสียเวลาและต้อง redo
