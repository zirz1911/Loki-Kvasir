## Honest Feedback

**1. สันนิษฐาน OwnTracks HTTP API เร็วเกินไป**
ผมเขียน `device = d or data.get("tid", "") or "phone"` โดยสันนิษฐานว่า `?d=` param จะมีอยู่เสมอ ต้องใช้ debug log round เพิ่มกว่าจะรู้ว่า OwnTracks ไม่ส่ง query params แต่ซ่อน device ใน `topic` field แทน ควร test actual payload ก่อนเขียน code

**2. pm2 env var ไม่ persist ตอน restart**
`LOCATION_REGISTER_SECRET` ต้องส่งผ่าน `pm2 start ... -e ENV=VAL` ทุกครั้ง ไม่ได้เก็บอยู่ใน pm2 config — ถ้า server reboot, env var จะหาย ควรสร้าง `ecosystem.config.js` หรือเขียน env ลง `.env` file แล้วใช้ `--env-file` แทน

**3. Physical skill ดึงข้อมูล repo ผิดมานาน**
`location-query.ts` ชี้ไปที่ `laris-co/nat-location-data` (FindMy format, 13 columns) มาตลอด แทนที่จะเป็น `zirz1911/Paji-Location` (OwnTracks format, 6 columns) ความผิดพลาดนี้ผ่านมาหลาย commits โดยไม่ถูกจับ เพราะไม่มี automated test ที่ verify output format

## Lessons Learned

**owntracks-http-topic-field**: OwnTracks HTTP mode ไม่ส่ง device ID ใน `?d=` query param — ส่งใน `topic` JSON field แทน (`owntracks/{username}/{deviceid}`) ก่อนสันนิษฐาน HTTP API ให้ log `request.json()` และ `request.query_params` ดูก่อนเสมอ

**cloudflare-tunnel-multi-ingress**: Cloudflare Tunnel รองรับหลาย hostname ใน ingress เดียว — ไม่ต้องสร้าง tunnel ใหม่ แค่เพิ่ม `- hostname: X` ใน `config.yml` แล้ว restart service
