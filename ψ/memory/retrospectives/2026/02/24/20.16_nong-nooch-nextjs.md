## Key Code Changes

- **Gallery lightbox**: `useState<GalleryItem | null>(null)` → click item opens modal, ESC closes via `useEffect` keydown listener
- **Shows date nav**: `dateOffset` state + `formatDate(offset)` using `BASE_DATE + offset days`
- **Shows reminder**: `useState<Set<string>>` to track which shows have reminders set
- **Checkout validation**: typed `FormField` union, per-field error map, pattern match for email, card number length check
- **Checkout success screen**: renders entirely different JSX tree with order reference
- **Virtual tour zones**: `transitioning` state (opacity fade 300ms) + `zoom` via array index into `[50,75,100,125,150,200]`
- **3D experience zones**: same transition pattern, background as inline `backgroundImage` string
- **Fragment key fix**: `import { Fragment }` + `<Fragment key={step}>` instead of `<>` shorthand

## AI Diary

This session was a study in two speeds: *construction* and *activation*. The first part — finishing virtual-tour and 3d-experience — was continuation work. Clean, methodical. I had the HTML originals, I knew what to convert. The `useEffect` overflow:hidden pattern, the glass-panel sidebar, the hotspot animation — all translated cleanly.

Then the user said the words that change everything: "ให้แต่ละฟีเจอร์ใช้งานได้จริงๆ". Make every feature actually work.

That's a different kind of task. It's not conversion — it's *judgment*. For each button, each toggle, each filter: what does "working" mean here? The gallery filter needed to hide items and show them — straightforward. But the lightbox was a design decision I made: click the image, get a fullscreen modal with ESC support. Not in the original HTML. But it felt right for a gallery.

The checkout was the most satisfying. Empty form → validation errors → success screen with order reference. A complete flow. The branching payment methods (card form vs PromptPay QR placeholder vs bank radio list) added depth without complexity.

The React Fragment key bug was a classic — `key` placed on `<div>` *inside* a `<>`, which React never sees because it can only track the outermost element. Simple fix, but it only surfaces at runtime in the console, not in TypeScript or build. A reminder that some errors live in the behavioral layer, not the type layer.

Most pleasing moment: `npm run build` producing 10/10 static pages, zero warnings, in under 2 seconds. That's a sign that the architecture is honest — no server-side logic masquerading as client work, no dynamic routes where static would do. Every page is genuinely prerenderable.

## Honest Feedback

**1. Parallel writes worked well but context juggling was real.** Rewriting 6 pages simultaneously meant holding the pattern of each in working memory. Gallery needs lightbox state. Shows needs Set for reminders. Checkout needs typed FormField union. Getting these all right without cross-contamination required deliberate focus. If one page had slipped a pattern from another, it would've compiled but behaved wrong — hard to catch.

**2. The "make it work" instruction is intentionally vague and that's fine — but it requires taste.** I had to decide: does "Set Reminder" toggle? Flash a toast? Show a modal? I chose toggle with a green "Reminder Set!" state because it's stateless (no backend), immediate, and satisfying. The user didn't specify — I filled in the design judgment. This is the right mode for this kind of work, but it means the output reflects my aesthetic choices, not just the user's intent.

**3. The Fragment key issue only shows in console, not build.** `npm run build` passed before the fix. TypeScript didn't catch it. Only the runtime React warning surfaced it. This is a class of error that static analysis doesn't reach — component-level correctness vs type correctness. Worth noting as a category: *build passes, lint passes, types pass, but behavior is wrong*. In production these accumulate silently.

## Lessons Learned

- `<Fragment key={val}>` required when returning multiple elements from `.map()` — `<>` shorthand doesn't accept props
- Next.js 16 static export works fine for client-only interactivity — `useState` pages still prerender as static HTML shells
- Inline `style={{ backgroundImage }}` safer than Tailwind arbitrary `bg-[url(...)]` when URLs contain `&` or special chars
- `useEffect` keydown listener for ESC on modals: return cleanup `() => window.removeEventListener(...)` or it leaks across navigations
