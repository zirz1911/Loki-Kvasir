## AI Diary

This was a satisfying little session — the kind where everything is small but the cumulative effect feels real. We opened World-Conflict for the first time, ran the dev server (it was already running, which was mildly surprising — a ghost from a previous session), and then worked through two meaningful tasks.

The map style task was interesting because Lokkji asked for "Map Default" and I interpreted that as both a rename *and* a tile change to OpenStreetMap. We went through the full cycle — rename, swap tile, test — and then reverted back to the Dark Matter CartoDB tiles when Lokkji decided the original dark aesthetic was preferable. That's a completely valid workflow: try something, see it, decide. No wasted effort, just discovery.

The data update was the meatier task. The mock data was frozen at late 2024 — reasonable when the project was born, but the world has moved. Assad fell in December 2024. Goma fell in January 2025. Gaza entered a fragile ceasefire. Sudan declared famine. These aren't minor updates — the geopolitical landscape shifted significantly in just two months. Pushing 2025–2026 data into the dashboard makes it feel like a real intelligence tool rather than a history exhibit. I updated 23 conflict hotspots, 10 active conflicts, 8 alert events, 8 casualty entries, 8 sanctions, 8 refugee datasets, and 10 intel feed events — all reflecting the state of the world as of early 2026.

One honest observation: mock data will always be mock data. The numbers I used are as accurate as my training allows (cutoff August 2025), but for a dashboard that aspires to be a real monitoring tool, the next evolution should be live API integration — ACLED, UNHCR, OCHA, GDELT. The scaffolding is already there; it's just a matter of wiring it up.

## Honest Feedback

**1. The dev server ambiguity was jarring.** When I tried to start the dev server, it failed with a lock file error because one was already running. This is a minor friction point but it surfaces a real question: is there a process manager keeping track of what's running? On Windows with multiple projects (WorldMap, World-Conflict, Loki Oracle), process management gets messy. A quick `ps aux | grep next` equivalent or a tmux session list would help orientation.

**2. Iterative rename/revert is fine but signals indecision in the spec.** The "Dark Matter" → "Map Default" → "Dark Matter" cycle was three edits across four files for zero net change. This isn't a problem with the workflow — it's discovery-driven development. But it points to a pattern: when the ask is visual/aesthetic ("make it look like X"), a quick screenshot or mockup preview step before committing code changes would save time. The intent was clear in hindsight but ambiguous upfront.

**3. Mock data quality is asymmetric.** Some data (Ukraine, Gaza, Sudan) is well-documented and accurate. Other data (DRC casualty numbers, Sahel exact figures) has wider uncertainty bands. A future improvement would be flagging data confidence levels in the interface — e.g., "Est. 2025" vs "ACLED verified" — so the dashboard communicates its own epistemic status.

## Lessons Learned

- When a user asks to "change X to Y" for a named UI element, clarify whether they mean label-only or also the underlying behavior (tile URL, color, etc.) before making all changes
- World-Conflict and WorldMap are sibling projects sharing similar stack — patterns from one apply to the other
- Mock data has a shelf life; refresh cycles should be planned as part of project maintenance
