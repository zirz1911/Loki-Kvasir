## Lessons Learned

1. **"Native Linux" needs clarification — VirtualBox is not bare metal.** Always ask: "dual boot, separate machine, or VM?" before predicting USB behavior. VirtualBox USB passthrough has the same class of issues as WSL2 usbipd.

2. **VirtualBox USB passthrough creates a new host identity for ADB.** The phone authorizes per RSA key. Windows ADB key ≠ Linux VM ADB key. Revoking all authorizations on the device and re-authorizing under the target OS is the correct reset procedure.

3. **`lsusb` + `adb devices` together diagnose the full picture.** `lsusb` = hardware visible, `adb devices offline` = ADB layer reached but authorization blocked. Empty `adb devices` = either hardware not visible or ADB not running. This 3-state diagnosis is reliable.

4. **USB product ID reveals current mode.** `2717:ff20` = MTP/Charging (Xiaomi). `2717:ff48` = MTP + ADB. `18d1:d00d` = fastboot. These IDs are useful for confirming what mode the device is in before debugging further.
