## Honest Feedback

**Friction 1**: การแก้ zip บน Windows ด้วย Python text mode เป็น footgun ที่ชัดเจน ควรใช้ binary mode ตลอดตั้งแต่ต้น ปัญหานี้เกิดจากการที่ patch.py ถูกเขียนใน `patch.py` ด้วย `open(..., 'r')` และ `open(..., 'w')` โดยไม่ระบุ `encoding` หรือ `newline=''` ซึ่งบน Windows เป็น trap ที่คนส่วนใหญ่ไม่รู้จนกว่าจะโดน

**Friction 2**: ไม่มี automated verification step หลัง rebuild zip ก่อน session ที่แล้ว ควรมี checksum หรือ hex dump verification ว่า CRLF หายจริงก่อนส่งให้ user flash จะประหยัดรอบ flash ไปหนึ่งรอบ

**Friction 3**: workflow การแก้ zip บน Windows แล้วส่งกลับไป flash บนมือถือยังไม่ smooth ต้องอาศัย user transfer file ด้วยตัวเอง ถ้ามี ADB push automation หรือ network share จะเร็วกว่านี้มาก

## Lessons Learned

1. **Python text mode บน Windows = CRLF trap** — ใช้ `open(..., 'rb')` / `open(..., 'wb')` ทุกครั้งที่จัดการไฟล์ที่จะรันบน Linux/Android อย่าใช้ text mode กับ shell scripts เด็ดขาด
2. **CRLF signature บน POSIX shell**: `}: not found`, `return: not found`, `{: not found` ทุก line = `\r` ที่ end of line ใช้ `cat -A file | head` เพื่อ verify ทันที
3. **Verify zip content หลัง patch** — `python3 -c "import zipfile; data=zipfile.ZipFile(...).read(...); print(data.count(b'\r'))"` ก่อน flash เสมอ
4. **r0ttenbeef kernel module layout**: `.ko` files อยู่ใน `kernel/drivers/...` ไม่ใช่ `lib/modules/` — NetHunter installer ไม่ได้ handle layout นี้ ต้อง patch `push_modules()` เอง
