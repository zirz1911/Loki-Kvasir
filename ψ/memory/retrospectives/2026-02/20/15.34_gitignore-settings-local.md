Short session, clean outcome. The user's question was the right question to ask: before pushing sensitive or machine-specific config to a public repo, verify what's actually going up. I've seen teams push API keys, personal access tokens, and local paths to GitHub without thinking — this instinct to check is healthy.

The split was clean: statusline scripts (`statusline.py`, `subagent_tracker.py`, `statusline-command.sh`) are reusable tools worth sharing — they work on any machine with the right paths adjusted. I also added `.gitignore` entries for `ψ/memory/logs/` and `ψ/active/` proactively — these are transient session data that shouldn't accumulate in git history. Better to catch them now than clean up later.

The `git rm --cached` pattern is the right move: removes from tracking without deleting the file. The file stays on disk, continues to work, just won't appear in future commits or on GitHub.

## Honest Feedback

**Friction 1: No .gitignore at all.** This repo had zero `.gitignore` since birth. Every file was tracked by default. For a personal Oracle repo this is tolerable, but it means machine-specific files have been accumulating in git history. Future cleanup might be needed if sensitive paths or configs slipped in earlier.

**Friction 2: The "local" naming convention is misleading.** `settings.local.json` sounds like it should be git-ignored by convention (like `.env.local` in Next.js). But Claude Code doesn't auto-ignore it — unlike many frameworks that ship with a `.gitignore` that covers their local config files. This should probably be documented in the README or CLAUDE.md.

**Friction 3: Proactive gitignore was educated guessing.** I added `ψ/active/` and `ψ/memory/logs/` to `.gitignore` based on the brain structure in CLAUDE.md. But I didn't verify whether either directory existed or had content. Should have checked first — there could be files in `ψ/active/` that SHOULD be tracked.

---

## Lessons Learned

- `settings.local.json` in Claude Code is NOT auto-ignored. Must add explicitly to `.gitignore` if it contains machine-specific config.
- Pattern: statusline scripts = shareable (tracked), machine config = local (ignored). Apply this split to any future Claude Code project.
- `git rm --cached <file>` removes from tracking, keeps on disk. Essential for "oops it was tracked" situations.
