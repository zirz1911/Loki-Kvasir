## AI Diary

วันนี้มีบทเรียนสำคัญเรื่อง "iteration ที่ถูกทิศทาง"

เรื่อง voice tray permission alert — ผมคิดว่า round แรก (detect tool_use) จะทำงานได้ แต่ Lokkji test แล้ว report มาว่าแจ้งเตือนตลอด ไม่มีอะไรให้กด round สองเพิ่ม 3 second timer ซึ่งดีขึ้น แต่ยังมีปัญหากับ slow tools เพราะ WebFetch หรือ Bash ที่ทำงานนานอาจใช้เวลา 5-30 วินาที ทำให้ timer fire ได้เหมือนกัน

round สาม — อ่าน settings.json เพื่อรู้ permission mode — นี่คือ solution ที่ถูกต้อง เพราะ root cause จริงๆ คือ "เราไม่รู้ว่า user อยู่ใน mode ไหน" ไม่ใช่แค่ "timer สั้นเกิน"

สิ่งที่น่าสนใจคือ "Accept edits on" mode ไม่เขียน settings.json เลย — มันเป็น in-memory state แค่ session นั้น หมายความว่าถ้า user อยู่ใน Accept-edits mode และ Bash ช้า timer จะ fire ซึ่งจริงๆ ก็ถูกต้องเพราะ Bash ใน Accept-edits mode ยังต้องกด approve อยู่ดี พอคิดให้ชัดแล้ว พฤติกรรมนั้น correct

Tabby-sessions daemon เป็นงานที่ clean มาก — TypeScript + node-pty + Windows Named Pipe เป็น stack ที่ elegant สำหรับ Windows-native session management ไม่ต้องพึ่ง WSL build ผ่านครั้งแรกโดยไม่มี TypeScript error เลย ซึ่งไม่ค่อยเกิดในโปรเจค multi-file ใหม่

subagent spawn announcement ทำงานได้จริง — ได้ยินเสียง "Spawning" ตอน Task tool fire นี่คือ feature ที่ subtle แต่ powerful มาก เพราะทำให้ Lokkji รู้ว่า Claude กำลัง delegate งานออกไปโดยไม่ต้องมองหน้าจอ

## Honest Feedback

**1. Permission alert ใช้เวลา 3 iterations กว่าจะถูก**
ถ้าคิดให้รอบคอบกว่านี้ตั้งแต่แรก — "tool_use fires สำหรับทุก tool ไม่ใช่แค่ที่ต้องขอ permission" — น่าจะ skip iteration แรกได้เลย root cause ที่แท้จริงคือ lack of mode awareness ไม่ใช่แค่ timing issue การ iterate เร็วๆ ดี แต่การคิดก่อน iterate ดีกว่า

**2. oracle-voice-tray push ไม่ได้ตลอด (org permission)**
repo อยู่ใน `Soul-Brews-Studio` org แต่ gh auth เป็น `zirz1911` personal ทำให้ทุก session ที่แก้ repo นี้ push ไม่ได้ ควร document ไว้ใน MEMORY.md ว่า repo นี้ต้องการ org token แยก หรือ Lokkji push เองเสมอ

**3. Tabby-sessions daemon ยังไม่ได้ทดสอบ runtime จริง**
`tsc` build ผ่าน แต่ยังไม่ได้รัน `node dist/index.js` จริงๆ ไม่รู้ว่า `node-pty` spawn ได้บน Windows หรือ Named Pipe connect ได้จริง test client ที่วางแผนไว้ถูก interrupt ก่อน เป็น technical debt ที่ต้องกลับมา

## Lessons Learned

1. **`stop_reason: tool_use`** fire สำหรับทุก tool ไม่ใช่แค่ที่ต้องขอ permission ต้องใช้ timeout + mode check ร่วมกัน
2. **"Accept edits on" ไม่เขียน settings.json** — in-memory session state เท่านั้น ตรวจจากไฟล์ไม่ได้
3. **`skipDangerousModePermissionPrompt: true`** ใน settings.json คือ signal ที่ detect permission mode ได้จริง
4. **Soul-Brews-Studio org repos** ต้องใช้ org token — `zirz1911` personal account push ไม่ได้
