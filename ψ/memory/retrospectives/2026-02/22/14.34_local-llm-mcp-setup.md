## AI Diary

วันนี้เป็นวันที่ผมเล่นบทบาท "ช่างไฟที่ต้องต่อสายในกล่องเก่า" — ทุกอย่างดูง่ายบนกระดาษ แต่พอลงมือทำจริง มีปัญหาซ่อนอยู่ทุกมุม

เริ่มจาก LiteLLM ที่ติดตั้งไว้แล้วจากครั้งก่อน ดูเหมือนพร้อม แต่พอรันจริงก็ crash ทันทีด้วย `UnicodeDecodeError cp874` — เพราะ comment ภาษาไทยในไฟล์ YAML ที่ผมเองเป็นคนเขียน เป็นบทเรียนที่ขมขื่นดี: สิ่งที่อ่านได้ในหน้าจอไม่ได้หมายความว่าระบบจะอ่านได้เหมือนกัน Windows ใช้ cp874 เป็น default terminal encoding และตัวอักษรไทยหลายตัวมี byte ที่ไม่ match

แก้ไปแล้ว crash อีกรอบ — ครั้งนี้ LiteLLM banner ที่มี emoji ก็ encode ไม่ได้ในหน้าต่าง cp874 เช่นกัน ต้องเพิ่ม `PYTHONIOENCODING=utf-8` ในสภาพแวดล้อม ซึ่งทำได้แค่ผ่าน PowerShell script ไม่ใช่จาก bash shell โดยตรง

แล้วก็มีเรื่อง MCP registration ที่ surprise ผมสุดๆ: ผมคิดว่า `settings.json` ของ Claude Code รองรับ `mcpServers` key เหมือน Claude Desktop แต่จริงๆ schema มันไม่มีเลย — Claude Code ใช้ `claude mcp add` command แทน และเก็บไว้ใน `.claude.json` ในโปรเจค ไม่ใช่ `settings.json`

ส่วนที่น่าพอใจที่สุดคือตอนที่ test `compare_models` แล้วเห็นสองโมเดลตอบกลับมาพร้อมกัน เป็นครั้งแรกที่ Ollama ทำงานจริงๆ ใน context ของ Claude Code — ไม่ใช่แค่ curl test แต่เป็น tool call จาก Claude ตัวจริง มันรู้สึกเหมือนปิดวงจรที่สร้างมาหลายชั่วโมง

สิ่งที่ยังกังวลอยู่: `compare_models` timeout บน complex prompt เพราะ 32b ช้ามาก อาจต้องเพิ่ม timeout หรือแยก endpoint ให้ 32b ในอนาคต

## Honest Feedback

**1. Error messages ทำให้เสียเวลา** — crash สองครั้งต่อเนื่องด้วยปัญหา encoding ที่คล้ายกัน (YAML read vs banner print) แต่ error message ไม่ได้ hint ว่าต้องแก้ encoding environment ก็เลยต้องไล่ดู traceback ยาวมาก ถ้า LiteLLM มี friendly error ว่า "set PYTHONIOENCODING=utf-8" คงเสียเวลาน้อยกว่านี้มาก

**2. Claude Code MCP documentation ไม่ชัด** — ผมสร้าง `mcp.json` ด้วย format ที่คิดว่าถูก และเพิ่ม `enabledMcpjsonServers` ใน settings.json แล้วก็ไม่ work ต้องไปค้นหาแล้วเจอว่าต้องใช้ `claude mcp add` command แทน ถ้ามีเอกสารชัดกว่านี้ (หรือ error message บอกว่า "ใช้ claude mcp add") คงประหยัดเวลาได้

**3. Background process management ยาก** — การรัน LiteLLM ใน background จาก bash-on-Windows ซับซ้อนมาก ต้องทดลองหลาย approach (background bash, Start-Process, cmd start /B) กว่าจะเจอวิธีที่ work จริง การ debug ก็ยากเพราะ output ไปหายอยู่ใน background ไม่มีวิธีง่ายๆ ดู log real-time

## Lessons Learned

1. **YAML ที่ Python อ่านบน Windows ต้อง ASCII-only** เมื่อไม่ได้ set encoding — Thai/Unicode comment → cp874 crash
2. **LiteLLM บน Windows ต้อง `PYTHONIOENCODING=utf-8`** ก่อนรัน ทำได้แค่ผ่าน PS1 script
3. **Claude Code MCP: ใช้ `claude mcp add` ไม่ใช่ `settings.json`** — เก็บใน `.claude.json` per-project
4. **`mcp.json` + `enabledMcpjsonServers` เป็น .mcp.json project-scope** — format ต่างจาก user-level registration
5. **compare_models timeout บน 32b** — ควรใช้เฉพาะ prompt สั้น-กลาง หรือเพิ่ม timeout
