## AI Diary

มีปัญหาที่น่าสนใจมากในเซสชันนี้ — ทุก bug มี layer ของความละเอียดที่ซ่อนอยู่ข้างใน

EADDRINUSE recovery ดูง่ายตอนแรก แต่พอลงมือทำพบ race condition ที่ subtle มาก: ถ้าเขียน PID file ก่อน bind, second instance จะเขียนทับ PID ของตัวเอง แล้วตอน EADDRINUSE จะเจอ PID ตัวเอง ไม่ใช่ old daemon เรื่องนี้ต้องคิดลำดับเวลาให้ชัด — เขียน PID ต่อเมื่อ bind สำเร็จแล้วเท่านั้น มันเป็นตัวอย่างที่ดีของ "order matters in async systems"

Circular dependency `ipc.ts ↔ index.ts` ก็น่าสนใจ ผมลอง import cross-module ก่อน แล้วพบว่า Node.js จะให้ค่า undefined ตอน module loading ถ้ามี circular dependency ไม่ใช่ error ชัดเจน แต่เป็น subtle bug แก้ถูกด้วยการแยก `pid.ts` ออกมา เป็น single-responsibility ที่ทั้งสองฝั่ง import ได้

Win32 Input Mode เป็น bug ที่ผมไม่รู้จักมาก่อน ตอนแรกคิดว่าเป็น PTY buffer replay ที่ส่ง `\x1b[?9001h` ออกมา แต่จริงๆ มัน live output ที่ส่งหลัง attach PowerShell load เสร็จ test แรกของผมผิดเพราะคิดว่าจะเจอ sequence ใน buffer แต่มันอยู่ใน live stream ต้องรอ 1.5s ให้ PS โหลดก่อน ถึงจะ capture ได้

ที่น่าเจ็บใจหน่อยคือ user ต้องเผชิญ corrupted terminal จริงๆ ก่อนที่ผมจะเพิ่ม startup reset ถ้าคิดถึง case นี้ตั้งแต่ต้น (terminal corruption จาก previous session) ก็จะไม่เกิด ผมมักจะ fix ที่ "source of pollution" แต่ลืม fix ที่ "cleanup on startup" lesson: defensive terminal reset ต้องเป็น default ใน test-client ทุกตัวที่ต้องการ raw terminal

## Honest Feedback

**Friction 1**: สภาพแวดล้อม test ยุ่งยาก — shell cwd reset หลัง background process ทำให้ `node dist/index.js &` ใช้ path ผิด ต้องระวังและใช้ full path ตลอด ใช้เวลาหลาย iteration กว่าจะ stable

**Friction 2**: node-pty `AttachConsole failed` error ทุกครั้งที่ kill session ใน headless mode ดูน่ากลัวแต่ไม่ได้ทำให้ test fail จริง ต้องอธิบายซ้ำหลายครั้งว่า "ไม่ใช่ bug จริง" — อาจควรแก้ที่ต้นทางในสักเซสชัน

## Lessons Learned

1. **PID-before-bind = race condition**: ใน restart scenarios, เขียน PID file ต่อเมื่อ resource bind สำเร็จแล้วเท่านั้น ไม่ใช่ก่อน — prevent self-kill
2. **Circular imports ใน Node.js ไม่ throw error**: ให้ค่า undefined แบบ silent แก้ด้วยการแยก shared state ออกเป็น module กลาง
3. **Terminal mode pollution ข้ามเซสชัน**: PTY sequences เช่น `\x1b[?9001h` จาก shell A สามารถ corrupt terminal ที่รัน test-client ได้ต่อเนื่อง — ต้อง reset ทั้งตอน startup และ exit
4. **Win32 Input Mode ส่งเป็น live output ไม่ใช่ buffer**: PowerShell ส่ง `\x1b[?9001h` หลังจาก fully initialized ไม่ใช่ตอน spawn — test ต้องรอ async
5. **"Source of pollution" fix ไม่พอ**: ต้อง fix "cleanup on entry" ด้วย — defensive reset ที่ startup สำคัญเท่ากับการป้องกัน
