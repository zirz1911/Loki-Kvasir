## Honest Feedback

**Friction point 1: Explore agent cannot write files.**
This is architecturally correct (read-only exploration is safer) but it creates a workflow gap. I had to run Explore agents, harvest their detailed output from task notifications, then write the files myself. Three extra round-trips per repo. For future sessions: use general-purpose agents when writing is needed, Explore agents only for pure read tasks where output is returned to main context.

**Friction point 2: bash + UTF-8 ψ character encoding on Windows.**
Every time I tried to use `ψ` in a bash variable path, it broke. The workaround (hardcoded paths, Python, or separate commands) worked but was clunky. The root issue is bash on Windows (Git Bash / MSYS2) not handling UTF-8 directory names in variable expansion cleanly. Long-term fix: create a shell alias or always use absolute paths in bash contexts.

**Friction point 3: ghq not installed.**
Three repos attempted via ghq, fell back to `gh repo clone`. Not critical, but the /learn skill assumes ghq for path structure. Without it, the `origin/` symlink pattern breaks down — had to use `D:/ghq/zirz1911/` as a manual convention. Should document this workaround in memory or install ghq properly.

## Lessons Learned

1. **Explore agents = read only, general-purpose = read+write.** Route write tasks to general-purpose agents explicitly. Don't assume Explore can output files.
2. **Stack evolution as signal.** Reading a user's repo history chronologically reveals more than reading any single repo. 2022→2026 arc shows intent, not just capability.
3. **System prompts as docs.** gemgen's 500+ line system prompts serve double duty — AI instructions AND block type reference. This is a pattern worth reusing in any AI-first project.
4. **ψ paths in bash need hardcoding.** Never use ψ as a shell variable — always hardcode the full path when working in bash on Windows.
