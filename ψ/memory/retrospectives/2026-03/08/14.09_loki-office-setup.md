## Lessons Learned

1. **Read all target files in one parallel batch before editing** — listing which files will change before starting avoids mid-session "need to read X" interruptions. Map the territory, then move.
2. **bun PATH is not inherited by package.json scripts on fresh installs** — `bunx` fails if bun isn't in PATH. Either use full path in scripts, or document `source ~/.bashrc` before `bun run`. The ecosystem.config.cjs approach (hardcoded interpreter path) is the correct production pattern.
3. **Convention-based theming > config-based theming** — `ROOM_COLORS` keyed by session name means "name your tmux session `jotunheim` and it becomes Jotunheim automatically." No UI config, no lookup, just naming convention. This is the right pattern for systems that grow organically.
4. **Fork by copy, not by git fork** — when you want a clean history (no upstream baggage), `cp -r + rm -rf .git + git init` is cleaner than `gh repo fork`. The new repo owns its own story from commit 0.
